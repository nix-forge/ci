# Nix Forge CI v2.14.0

## Changelog

- Add explicit `read-only` consumers and trusted default-branch `seed` producers
  to the opt-in Nix store cache. Existing `auto` writer policy remains available.
- Separate cache identities by the installed Nix runtime, runner platform,
  workload, partition and lockfile hash. An unambiguous workload digest prevents
  boundary collisions. Compatible restores across lock changes require opt-in.
- Report effective substitute origins and public key names without URL secrets,
  matched cache keys, write eligibility and restore timing. Actual uploads and
  compressed transfer sizes remain the cache post-action's responsibility.
- Support bounded native-check evaluation batches, with isolated current fallback
  and conservative rebuilding when historical evaluation is unavailable. The
  default batch size remains one and accepted sizes range from one through eight.
- Require successful owning GitHub Actions checks on the exact base commit
  before skipping equal check derivations. Callers opt in with
  `base-success-checks` and read-only check access. Missing, pending, failed,
  truncated or unavailable evidence rebuilds current checks. No token reaches
  the subsequent Nix or Git child processes.
- Offer optional retained output roots so realized check artifacts survive
  post-job store collection. Required native host proofs remain caller-owned.

The 213 repository regression tests, pinned workflow/security validation and
full Linux flake checks passed locally. Actual Nix exercised nine difficult
attribute names, exact changed/base derivations and the build selector. The
representative workstation caller passed the shared validator and its focused
consumer regressions. Required hosted checks and the protected merge queue must
pass before tagging this release.

Consumers should update every shared reference together to the tagged commit.
The workstation consumer supplies a trusted producer for reviewed public static
profiles, read-only consumers and explicit successful-base aggregate names.
Native/private or redistribution-restricted store contents require their own
publication review. No external cache service or publication credential is added.
Cold/restored hosted measurements are pending; this release claims no measured
speedup. Restoring the previous reviewed v2.x SHA rolls back the action changes.
Compatible v2.x consumers have no scheduled support end date.

The signed tag and verified release manifest identify the protected source
commit. Publication verifies the source archive and provenance subjects against
the independently pinned SLSA builder. No required native checks, queue admission
permissions or release-verification gates are removed.
