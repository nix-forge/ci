# Nix Forge CI v2.13.0

## Changelog

- Reconcile all eligible package-source heads on a completion notification.
  This recovers ready heads when workflow concurrency replaces a pending callback.
- Read current PR identity, source refs and latest statuses in a GraphQL batch.
  Use a bounded native check-suite projection to defer healthy partial producers
  and recognize unchanged already-admitted results without writes.
- Preserve full immutable source, workflow, current-run and actual-job proofs
  for every new result or admission. Real failures retain their actual job URLs
  when another producer is running or absent. Changed attempts invalidate old
  source results. Truncated, missing and approval-only projections take the
  complete validation path.
- Replace callback workflow-name lookup with one direct dispatch request.
  Preserve legacy queue callback inputs and bounded visible notification retries.
- Pace opted-in package reconciliation content writes four seconds apart, including status,
  enqueue and validation dispatch requests. Package-source callers must allow
  15 minutes in their own reconciler jobs for a paced six-head sweep.

A finite six-package fixture executes the actual reconciler for source
notifications and all 30 queue completion callbacks. It preserves all 19 queue
results and includes notification and candidate-dispatch requests. That fixture
uses 831 REST requests. A separate 99-request source-inspection allowance brings
the normal accounting model to 930 requests. Live read-only GraphQL queries for
the PR snapshot and six distinct native source heads each cost one point.

GitHub's standard repository token allows
[1,000 REST requests per hour](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api).
Repeated reruns, updater requests and delayed producer completion consume
additional requests. Completion callbacks retain their bounded wait when the
producer is still running. These counts do not promise capacity for unlimited
reruns or simultaneous unrelated automation. Real native validation can span
multiple quota windows.

Existing source start notifications remain asynchronous. They do not acknowledge
that the reconciler has completed its status writes. Source completion
notifications remain blocking after all actual validation jobs.

No token permissions or required native job gates change. The independently
reviewed release-builder and repository-checks pins remain separate. Consumers
without package-source reconciliation retain their existing callback contract.

The 189 repository regression tests passed locally. Required hosted validation
and the protected normal merge queue must pass before publication. The signed
tag and verified release manifest identify the protected source commit.
Publication verifies the archive checksum and all release provenance subjects
against the separately pinned SLSA builder. Restore the previous reviewed v2.x
pin to roll back. Compatible v2.x consumers have no scheduled support end date.
